🧭 Overview & Key Definitions

Exam reality: Foundational level, comparable to AWS Cloud Practitioner but focused on AI/ML/GenAI. High-level & conceptual. Realistically one focused weekend of study if you have basic AWS familiarity.

General AI

Systems that can perform any intellectual task a human can — the long-term goal. Examples: Expert Systems, Rules Engines (e.g., MYCIN) which use predefined logic/rules.

Machine Learning (ML)

Subset of AI. Systems that learn from data to make predictions without explicit programming. Examples: Linear Regression, Decision Trees, Support Vector Machines.

Deep Learning

Subset of ML using multi-layered neural networks ("deep") for complex patterns. Examples: CNNs for images, RNNs for sequential/time-series data.

Generative AI

Subset of deep learning that creates new content (text, images, music) based on foundation models — large pre-trained models adaptable to many tasks. Examples: ChatGPT, DALL·E.

Large Language Models (LLMs)

Type of Generative AI focused on understanding and generating human-like text. Trained on vast text data. Examples: GPT-4, BERT, T5, Claude.

💡 Core GenAI Concepts

In-Context Learning

Enhancing models by adding data/examples directly to the prompt.

Few-Shot / One-Shot / Zero-Shot

Few = several examples in prompt. One = exactly one example. Zero = no examples, model performs blind.

Chain-of-Thought

Prompt encourages the model to break reasoning into steps ("Let's think step by step").

Prompt Template / Tuning

Pre-defined format to standardize prompts. Tuning = adjusting prompts to improve output.

Tokens

Basic text units (words/subwords/characters) processed by language models — both input & output.

Context-Window

Max tokens an LLM can process at once (input + output). Exceeding it truncates earlier text.

Embeddings

Numerical vector representations capturing semantic meaning. Stored in vector DBs for semantic search.

Latent Space

Encoded knowledge/patterns in an LLM storing relationships between data.

Multi-Modal Models

Work across multiple data types (text, images, audio) in a shared space.

🚨 Hallucinations & Mitigations

When a model generates incorrect/nonsensical info that sounds plausible but isn't grounded in facts.

  • RAG — retrieve relevant external data during generation to ground responses.
  • Fine-Tuning — train on more accurate/relevant data.
  • Human-in-the-Loop (HITL) — human review in low-confidence areas.

🔍 Search Methods

  • Keyword Search — matches exact terms.
  • Semantic Search — uses embeddings to understand meaning behind queries.

⚙️ The ML Pipeline (8 Steps)

1
Identify Business GoalDefine success metrics & align stakeholders.
2
Frame ML ProblemDefine inputs/outputs/metrics; cost-benefit analysis. Model options: AI/ML Hosted Service (Comprehend, Forecast — no training), Pre-trained (Bedrock, JumpStart — fine-tune), Fully Custom.
3
Collect DataStore in Amazon S3. Tools: AWS Glue (ETL), SageMaker Ground Truth (human labeling), AWS Data Exchange (third-party datasets).
4
Pre-Process DataEDA, clean data, anonymize PII. Split: 80% train / 10% validation / 10% test. Tools: AWS Glue, Glue DataBrew (visual, "recipes"), Macie (PII detection), SageMaker Canvas (no-code).
5
Engineer FeaturesSelection, creation, transformation (normalization, one-hot encoding). Use SageMaker Autopilot (auto feature gen/rank), PCA (dimensionality reduction). Store in SageMaker Feature Store.
6
Train, Tune, EvaluateTune hyperparameters; evaluate with metrics. (Details below.)
7
DeployReal-time / Batch / Asynchronous / Serverless inference.
8
MonitorDetect data drift & concept drift with SageMaker Model Monitor.

Step 6 Deep Dive — Parameters

Inference Parameters (Amazon Bedrock)

ParameterEffect
TemperatureHigher = more creative/diverse. Lower = deterministic. Use for consistent randomness control.
Top KLimits to top K probable tokens. Smaller K = safer. Not very useful — use Temperature or Top-P instead.
Top PCumulative probability token selection. Higher (closer to 1) = less random. Use for adaptive diversity.
Response lengthMax output length (verbose vs. concise).
PenaltiesPenalize repeated tokens/sequences for variety.
Stop sequencesSpecific sequences where generation stops.
Temperature vs Top-P: Temperature scales probabilities across all tokens. Top-P narrows to a probability threshold. Use Top-P for adaptive diversity staying close to likely outcomes; use Temperature for consistent randomness control.

Training Parameters (Hyperparameters)

  • Epoch — iterations through entire dataset. More = better learning, but risk of overfitting.
  • Batch Size — samples before updating params. Smaller = faster convergence but noisier; larger = stable but more compute.
  • Learning Rate — how fast the model learns. High = fast but may skip optimum; low = precise but slow, risk of local minima.

Error Metrics

MetricMeasuresRule of Thumb
MSEAvg squared error; weights larger errorsLower better. Regression (house prices).
RMSESqrt of MSE; same unit as predictedLower better. More interpretable.
PerplexityHow well model predicts next tokenLower better. Language models.
PrecisionTrue positives ÷ total predicted positivesHigher when false positives costly (spam).
Recall (TPR)True positives ÷ actual positivesHigher when false negatives costly (medical).
FPRFalse positives ÷ total negativesLower better (fraud, alarms).
Specificity (TNR)True negatives ÷ actual negativesHigher better for identifying negatives.
AccuracyCorrect ÷ total predictionsHigher better. Balanced classification.
F1 ScoreHarmonic mean of precision & recallHigher better. Balance FP & FN.
ROC Curve / AUCTPR vs FPR across thresholdsHigher AUC better. Binary classification.

Training Issues

  • Overfitting — too much training on same data, model overly specific. Fix: more diverse data.
  • Underfitting — model doesn't learn enough patterns. Fix: more epochs / more data.
  • Bias & Fairness — lack of diversity → biased predictions. Fix: diverse representative data + fairness constraints.

🔄 MLOps & Automation

Apply DevOps principles to manage ML models across their lifecycle: automation, version control, monitoring.

  • SageMaker Pipelines — automate ML workflow end-to-end.
  • AWS CodePipeline — automate build/test/deploy.
  • SageMaker Model Registry — manage & track model versions/metadata.
  • Amazon S3 — store trained model artifacts/weights (SageMaker & Bedrock).

⚖️ Model Governance & Explainability

Transparency, accountability, regulatory compliance, and interpretable behavior.

  • SageMaker Clarify — detect bias, explain predictions, increase transparency.
  • SageMaker Model Cards — documentation (performance, intended use).
  • ML Governance (SageMaker) — control & visibility; track bias.
  • SageMaker ML Lineage Tracking — capture workflow, model lineage for reproducibility.
  • Glue DataBrew — data governance with visual quality rules.
  • AWS Audit Manager — automate auditing, compliance.
  • AWS Artifact — compliance reports & agreements.
  • AWS AI Service Cards — transparency docs (use cases, limitations, responsible AI practices).

💰 Cost & Performance Optimization

  • AWS Trusted Advisor — cost/performance/security recommendations.
  • SageMaker Managed Spot Training — use spare EC2 capacity to cut training cost.
  • SageMaker Profiler — identify inefficient resource use during training.
  • Amazon Inspector — automated security assessments.

🔐 Security

  • Least Privilege — IAM roles/policies grant only required permissions.
  • PrivateLink & VPC Endpoints — lock down SageMaker; prevent internet exposure.
  • Encryption at Rest & in Transit — SageMaker encrypts via KMS by default.
  • S3 Block Public Access — prevent model data exposure.
  • AWS IAM Identity Center — centralize identity; integrate with Active Directory.
  • AWS Config — monitor/record config changes for compliance.
  • AWS CloudTrail — log API calls, track user activity.
  • SageMaker Role Manager — simplify permissions management.

🧱 AWS Glue

Fully managed, cloud-optimized ETL service for data prep & analytics.

  • Glue ETL Service — built-in transformations (drop duplicates, fill missing). Workflow: Kinesis Data Streams → Glue ETL → CSV to Parquet → S3 Data Lake.
  • Glue Data Catalog — centralized metadata repository (schemas, not data); built-in classifiers.
  • Glue DataBrew — visual data prep; data quality rules saved as "recipes".
  • Glue Data Quality — detect anomalies; recommend quality rules.
